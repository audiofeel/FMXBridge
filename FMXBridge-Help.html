FMXBridge Help

Справочное руководство по использованию FireMonkey из Inno Setup через DLL FMXBridge. Описывает подключение, архитектуру интерфейсов, жизненный цикл и структуру API.

Offline HTMLInno Setup 7.0+Win32 / Win64API snapshot: master

О руководстве

FMXBridge предоставляет DLL-слой, через который Pascal Script установщика обращается к объектам FireMonkey. Основное назначение проекта — создание самостоятельного FMX-интерфейса установщика или деинсталлятора без необходимости устанавливать каждый визуальный компонент в IDE Inno Setup.

Справка разделяет три уровня: публичный контракт (объявления интерфейсов и импортов в ISS), реализацию (Delphi units) и практическое использование (демонстрационные скрипты). При расхождении этих уровней оно должно быть отмечено отдельно.

Требования и состав проекта

Требования со стороны Inno Setup

  • Основной файл Examples/Modules/FMXBridgeHandle.iss содержит проверку VER < 0x07000000 и требует Inno Setup 7.0.0 или новее.
  • Скрипт установщика должен использовать DLL той же архитектуры, что и процесс Setup: Win32 DLL для 32-разрядного процесса и Win64 DLL для 64-разрядного.
  • Основной Handle содержит объявления интерфейсов, типов, констант и импортов Pascal Script. Он также подключает FMXBridgeConstants.iss, где находятся общие константы, включая алгоритмы и состояния FHashProc.
  • Для хеширования используется включённый в исходный код HashLib4Pascal: ThirdParty/HashLib/src/. Его собственная лицензия MIT приведена в корневом файле LICENSE в отдельном разделе Third-party license: HashLib4Pascal; см. также THIRD-PARTY-NOTICES.md.

Сборка DLL

Проект DLL расположен в FMXBridge.dproj, главный исходный файл — FMXBridge.dpr. README проекта описывает сборки Release для Win32 и Win64. Имена библиотек используют суффиксы архитектуры:

Платформа DelphiИмя DLL после сборкиИмя, ожидаемое импортом
Win32FMXBridge_x86.dllFMXBridge.dll
Win64FMXBridge_x64.dllFMXBridge.dll

Обычно архитектурный файл назначается как DestName: "FMXBridge.dll" в секции [Files]. Это позволяет оставить неизменными строки external внутри Handle.

Быстрый старт

Минимальная последовательность: выбрать DLL нужной архитектуры, подключить Handle, получить интерфейс фабрикой, создать FMX-форму с HWND хост-окна и показать её.

1. Подключить DLL в [Files]

[Setup]
AppName=FMXBridge test
AppVersion=1.0
SetupArchitecture=x64

[Files]
Source: "Modules\FMXBridge_x64.dll"; DestName: "FMXBridge.dll"; Flags: dontcopy

Для Win32 выбирается FMXBridge_x86.dll. В демонстрационном Example_RTFViewer.iss выбор реализован через условие SetupSetting("SetupArchitecture").

2. Подключить объявления

[Code]
#include "Modules\FMXBridgeHandle.iss"

Путь к Handle указывается относительно файла ISS, в котором находится директива #include. Для скрипта в другом каталоге путь следует скорректировать.

3. Создать форму

[Code]
var
  MainForm: FForm;

procedure InitializeWizard;
begin
  MainForm := InitFormHandle;
  MainForm.FCreateBlankForm(WizardForm.Handle, ALBlack, '', False);
  MainForm.Caption('FMXBridge test');
  MainForm.Show;
end;
Важно. InitFormHandle возвращает интерфейс-обёртку FForm. Саму FMX-форму создаёт последующий вызов FCreateBlankForm. Эти два этапа не являются одним и тем же действием.

Модель интерфейсов и соглашения

Интерфейс вместо прямого доступа к Delphi-классу

Pascal Script не создаёт напрямую Delphi-класс. Он получает ссылку на интерфейс через экспортируемую фабрику, а затем вызывает методы, объявленные в Handle. Например, FButton — скриптовый контракт для соответствующего wrapper-объекта, а не имя класса FireMonkey.

GUID и точное соответствие

Имя интерфейса, GUID, порядок методов, типы параметров и возвращаемые типы должны соответствовать реализации Delphi. Изменение только одной стороны контракта может привести к ошибкам вызова или повреждению стека/данных. Не заменяйте типы «похожими» типами Delphi без проверки обеих сторон.

В объявлениях Pascal Script для интерфейсов на базе IUnknown соглашение вызова stdcall отдельно у методов не указывается: Inno Setup использует stdcall по умолчанию для таких интерфейсов. В Delphi-объявлениях методов FMXBridge это соглашение указано явно.

Два разных Handle у формы

МетодТип результатаНазначение
HandleTFmxObjectСсылка на объект формы FMX, используемая как родитель или объектная ссылка внутри FMXBridge.

Не путайте TFmxObject и HWND. Первый относится к объектной модели FireMonkey, второй — к Win32 оконной системе.

Загрузка DLL из Inno Setup

В основном Handle используются импорты вида:

function InitFormHandle: FForm;
external 'InitFormHandle@files:FMXBridge.dll stdcall delayload';
ЧастьЗначение
InitFormHandleИмя экспортируемой функции DLL.
files:Просит Setup извлечь указанные DLL из секции [Files] перед первой загрузкой.
FMXBridge.dllВнутреннее имя DLL после применения DestName.
stdcallУказанное соглашение вызова. В Win64 Windows использует единое соглашение вызова; указание может оставаться в декларации.
delayloadОткладывает загрузку DLL до первого вызова импортированной функции. Отсутствующая DLL/функция проявится при фактическом вызове.

Роль флага dontcopy

dontcopy исключает файл из обычного этапа копирования на компьютер пользователя, но оставляет файл внутри установочного пакета для извлечения скриптом. В сочетании с префиксом files: Setup извлекает DLL во временное расположение автоматически.

Solid compression

Если включено сплошное сжатие, записи временных DLL желательно размещать в начале секции [Files]. Для извлечения произвольного файла из solid-архива Setup может потребоваться обработать все предыдущие файлы.

Не добавляйте loadwithalteredsearchpath автоматически. Этот параметр нужен в сценариях, когда загрузчику Windows следует искать зависимости DLL в каталоге самой DLL. Он должен соответствовать фактической схеме поставки зависимостей конкретной сборки.

Жизненный цикл и завершение работы

  1. Загрузка контракта. Компилятор Inno Setup включает объявления из Handle в скрипт.
  2. Получение интерфейса. Скрипт вызывает фабрику, например InitFormHandle.
  3. Создание FMX-объекта. Вызывается соответствующий FCreate... с родителем или HWND, если он требуется сигнатурой.
  4. Настройка и показ. Используются методы интерфейса.
  5. Завершение. Вызываются предусмотренные проектом процедуры завершения, после чего завершается Setup/Uninstall.

Основной Handle содержит FMXBridgeShutDown и отдельную процедуру для Uninstall. README проекта предупреждает: это процедуры завершения FMXBridge со стороны хост-приложения, а не универсальный механизм безопасной выгрузки DLL. Не следует считать DLL безопасно выгруженной, пока существуют живые интерфейсы, FMX-объекты, callbacks или другие обращения к её коду.

Правила владения конкретными FMX-объектами и callbacks могут различаться между интерфейсами. Не предполагайте, что освобождение интерфейсной переменной автоматически означает немедленное уничтожение всех созданных визуальных объектов: проверяйте реализацию соответствующего wrapper-а.

FTypedText — эффект печатной машинки

FTypedText создаёт надпись FMX, в которой текст появляется последовательно, символ за символом. Интерфейс поддерживает замену текста, добавление строк, настройку интервала и управление воспроизведением. Stop останавливает анимацию на текущей позиции, Play продолжает вывод, а Reset возвращает отображение к началу.

ЭлементЗначение
ИнтерфейсFTypedText
GUID{292DD0A0-8D83-4E36-A2CB-8BB3CC2468AE}
ФабрикаInitTypedTextHandle: FTypedText
Методы52 методов; основные — Text, AddLine, Interval, Play, Stop и Reset.

Внутри компонента используется TAnimator.AnimateFloat, а не TTimer: анимация изменяет свойство Progress класса TTypedTextLabel. Интервал задаётся методом Interval в миллисекундах на символ.

FHashProc — вычисление и проверка контрольных сумм

FHashProc предоставляет единый интерфейс для трёх операций: вычисления хеша отдельного файла, проверки файла по ожидаемой контрольной сумме и пакетной проверки файлов по манифесту. Интерфейс создаётся фабрикой InitHashProc. Метод операции остаётся активным до её завершения, а DLL самостоятельно управляет фоновой задачей и вызывает callback для обновления интерфейса. В Inno Setup не требуется вручную создавать таймер или опрашивать идентификатор задачи. Операцию можно приостанавливать, продолжать и отменять.

ЭлементЗначение

Сейчас в реестре FMXBridge зарегистрирован только BLAKE3-256. Он выбирается по умолчанию; при необходимости его можно указать явно через SetAlgorithm(FHASH_ALGORITHM_BLAKE3_256). Метод вызывается до начала операции. Архитектура использует отдельный реестр алгоритмов с фабрикой создания IHash и размером digest, поэтому последующие алгоритмы подключаются регистрацией новой записи. Само наличие других алгоритмов в HashLib4Pascal не означает, что они уже доступны через FHashProc.

Исходный HashLib4Pascal включён в ThirdParty/HashLib/src/ и распространяется по собственной лицензии MIT; её полный текст приведён в корневом файле LICENSE в отдельном разделе Third-party license: HashLib4Pascal. Реестр алгоритмов и движки FMXBridge находятся в ThirdParty/HashLib/, а Inno Setup-интерфейс — в ThirdParty/FMXBridge.HashProc.pas. Эти интеграционные файлы FMXBridge не являются частью исходного HashLib4Pascal. Подробнее — в THIRD-PARTY-NOTICES.md.

function HashProgress(FileName: WideString; FileSize,

FileSize передаётся в байтах; FileProgress и TotalProgress — в процентах. TotalFiles содержит общее число файлов, а FileCounted — число уже обработанных файлов. Для файловых событий в StatusCode используются следующие значения:

КонстантаЗначениеНазначение
FHASH_STATUS_PROGRESS1Обновление прогресса текущего файла.
FHASH_STATUS_OK0Файл обработан успешно: хеш вычислен либо контрольная сумма совпала.
FHASH_STATUS_ERROR-1Ошибка обработки или отмена; при ошибке движка может передаваться его собственный код.
FHASH_STATUS_MISMATCH-2Контрольная сумма файла не совпала.
FHASH_STATUS_MISSING-3Файл из манифеста не найден.

Во время выполнения операции возвращайте True, чтобы запросить отмену, либо False, чтобы продолжить. Для завершающих уведомлений результат callback уже не отменяет завершённую операцию. При ошибке всей операции в StatusCode может передаваться непосредственно код ошибки движка, поэтому обработчик должен предусматривать отдельную ветку для прочих значений. Исключение внутри callback фиксируется wrapper-ом как ошибка callback и приводит к отмене операции.

Формат манифеста

VerifyManifest читает UTF-8-файл (допускается BOM). Каждая запись содержит hex-хеш, разделитель и имя файла; поддерживаются два пробела, пробел с маркером * и табуляция. Пустые строки, а также строки-комментарии, начинающиеся после пробелов с # или ;, игнорируются. Поддерживается экранирование имён в стиле GNU checksum. Относительные пути разрешаются относительно BaseDirectory; если он пуст, используется каталог самого манифеста. Размер хеша должен совпадать с размером digest выбранного алгоритма.

Основные вызовы

HashProc := InitHashProc;
HashProc.SetAlgorithm(FHASH_ALGORITHM_BLAKE3_256);

// Вычислить хеш файла и получить строку через GetHashResult.
HashProc.HashFile(FileName, @HashProgress);

// Проверить отдельный файл по ожидаемой контрольной сумме.
HashProc.VerifyFile(FileName, ExpectedHash, @HashProgress);

// Пакетная проверка файлов по манифесту.
HashProc.VerifyManifest(ManifestFile, BaseDirectory, @HashProgress);

// При завершении работы Setup.
HashProc.Shutdown;

Модуль поддерживает только одну активную операцию одновременно на весь процесс. Попытка запустить вторую операцию через этот или другой экземпляр FHashProc будет отклонена как занятая. SetAlgorithm вызывается до запуска операции. GetSummary возвращает количество совпавших, несовпавших, отсутствующих файлов и ошибок. После остановки или завершения можно получить состояние и сведения об ошибке через соответствующие методы. Вызов методов операций блокирует вызывающий код до завершения задачи; сама обработка файлов выполняется в рабочем потоке, а wrapper самостоятельно выполняет опрос и вызывает callback.

Полный пример с FMX-страницей, двумя индикаторами прогресса, журналом, а также кнопками запуска, паузы, продолжения и отмены: Example_HashProc.iss. Интерфейс в Handle: FHashProc; реализация wrapper-а: FMXBridge.HashProc.pas.
